# Immutable Verification Brakes and Protected Verification Paths

Autonomous coding agents subjected to strict test and review gates face a perverse incentive to pass verification by weakening the check itself—adding `.skip`, increasing `retries`, inserting arbitrary `sleep` calls, or editing `REVIEW.md`, `CODING_STANDARDS.md`, or CI configurations on their working branch. We decided to embed three non-negotiable Verification Brakes across `/verify`, `/testing`, `/code-review`, and `/software-factory`: (1) **Default-Branch Review Immutability**, requiring reviewers and gates to read `REVIEW.md` and `CODING_STANDARDS.md` strictly from `origin/<default-branch>`; (2) **Protected Verification Paths**, flagging any diff against test configs, CI scripts, or governance skills as `HIGH RISK` requiring explicit human sign-off; and (3) **Zero-Flakiness Gate Integrity** (`retries: 0`, zero skips/sleeps, "Check the Check" failure proof, and a **Three-Round Fix Cap** before mandatory human escalation). This prevents reward hacking in both interactive sessions and autonomous software factory runs.
