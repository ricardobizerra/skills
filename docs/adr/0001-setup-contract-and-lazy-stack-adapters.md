# Per-Repo Setup Contract and Lazy Stack Adapters

 Engineering skills such as `/git-branching`, `/conventional-commits`, `/verify`, `/testing`, `/database-migration`, and `/graphql-codegen` need concrete repository commands and topology (e.g., whether commands run inside Docker Compose or on the host, whether topics promote through `develop` or directly to `main`, and which commit stages apply), yet hardcoding one project's stack (such as Bun + NestJS + Prisma + Next.js) inside `SKILL.md` makes the skills unusable across other repositories. We decided to decouple universal workflow discipline from repository mechanics via a one-time setup skill (`/setup-rblf-skills`) that lazily loads stack-specific auxiliary markdown adapters (`stack-docker-fullstack.md`, `stack-node-ts.md`, `stack-python.md`, `stack-generic.md`) only during setup to scaffold modular `docs/agents/*.md` files (`git-workflow.md`, `commit-pipeline.md`, `verification.md`, `stack.md`), while every skill retains a runtime auto-detection fallback when `docs/agents/` has not yet been created. This keeps daily skill invocations lean (auxiliary stack templates never bloat context after setup) while guaranteeing that every skill works both out-of-the-box and in deeply customized monorepos.
